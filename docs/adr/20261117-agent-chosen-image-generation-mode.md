# The agent chooses the Image generation mode per call

ADR 0002 let only the user's setting pick the Image generation mode, once per session. Agents could not reach OpenAI mode's SVG, GIF, or exact sizes in a Codex-mode session, or use the Codex allowance in an OpenAI-mode session. `generate_image` now takes an optional `mode` argument (`openai` or `codex`) and accepts both modes' arguments, rejecting the ones the chosen mode does not support. The setting is renamed `defaultImageGenerationMode` and picks the mode for calls without `mode`. The tool description tells the agent to switch only when the user asks or the task needs a feature only the other mode has, and never to retry a failed call in the other mode unless the user asks. ADR 0002's no-fallback rule stands: the tool never switches modes on its own.

We accept that an agent may spend OpenAI API credits in a session whose default is Codex mode, or the Codex allowance in the reverse case. Each call and its tool card name the mode, approval-gated sessions show it before the call runs, and no setting locks switching off. We rejected a session switch tool that re-registers `generate_image`, because it adds session state and depends on mid-turn re-registration reaching the next model request, which was unproved on OMP 18.22.0. We rejected one tool per mode because it puts two image tools in every request. We rejected naming the setting `defaultProvider`, because "provider" already means an OMP model provider and `codex` is not one.

A stored `imageGenerationMode` without `defaultImageGenerationMode` fails every call with the command that sets the new key. Ignoring the old key would silently move users who chose Codex mode onto OpenAI API credits, and reading it as an alias would keep two names for one setting.
