Advisor concern wake: more than 2 wakes, no endless loop

This page tells what the extension does now, why it has a limit of 2, and what I recommend to change.

Words on this page

Advisor
A second model. It reads each turn of the agent and can send notes to the agent.
Concern
An advisor note of medium importance. A nit is less important. A blocker is more important.
Card
The box in the chat that shows a concern. The agent can also read the card.
Wake
The extension starts a new agent turn, so that the agent examines the concern.
Prompt cycle
All work from one prompt that you send until your next prompt.

01What the extension does now

  1. You send a prompt. The agent does the work and gives a final answer.
  2. The advisor reads that turn. It can send a concern after the final answer.
  3. OMP shows the concern as a card. OMP does not start the agent again.
  4. The extension starts the agent again: a wake. The agent reads the card and examines the concern.
  5. The extension does this a maximum of 2 times in one prompt cycle.

02Why the limit exists

The advisor also reads the turn that a wake starts. It can send a new concern about that turn. The new concern causes a new wake. Without a limit, this loop can continue without end.

Figure 1 · The loop today, and where the limit stops it

03The problem with the limit

  • The limit counts wakes. It does not look at what the agent did after each wake.
  • Thus, a 3rd real problem gets no wake, also when the agent fixed the first 2 problems correctly.
  • The extension does not tell you that it stopped. You see only a card.

04Recommended change: 3 questions

Before each wake, the extension asks 3 questions. It wakes the agent only when all 3 answers are "yes".

  1. Is the concern new? OMP's judge (the TypeSafe Jev model) compares the concern with the concerns that the agent examined in this prompt cycle. If it finds the same issue, do not wake. The agent already gave its answer. If Jev is not available, the extension compares the words.
  2. Did the last wake change files? Look at the tools that the agent used after the last wake. If the agent did not edit files and did not run a command, it did not agree with the advisor. Do not wake again. For the first wake, the answer is "yes".
  3. Are there fewer than 6 wakes? This is only a safety limit. Question 1 and question 2 usually stop a loop before this.

When question 2 or question 3 stops a wake, the extension shows you a message. The card stays. You decide: send a prompt if you want the agent to act.

05Two examples

Example A · real problems

The new rules continue

  1. ADVISOR
    "The test for the new option is missing."
    wake 1
  2. AGENT
    Adds the test. Files changed.
  3. ADVISOR
    "The new test does not examine the error case."
    new concern · files changed → wake 2
  4. AGENT
    Adds the error case. Files changed.
  5. ADVISOR
    "The README does not tell about the new option."
    new rules: wake 3 · today: card only, no message

Example B · disagreement

The new rules stop

  1. ADVISOR
    "This function can return null."
    wake 1
  2. AGENT
    Reads the code. Answers: "It cannot return null." No files changed.
  3. ADVISOR
    "Make sure that this function cannot return null."
    almost the same → card only (question 1)
  4. ADVISOR
    A different concern.
    last wake changed no files → card + message to you (question 2)

06What you will see

When question 2 or question 3 stops a wake, a message like one of these shows at the bottom of the screen:

Advisor concern not sent to the agent: the agent changed no files after the last concern. Send a prompt if you want the agent to act.
Advisor concern not sent to the agent: 6 wakes in this prompt cycle. Send a prompt if you want the agent to act.

08Risks

  • Jev can find "the same issue" by mistake. Without Jev, two different concerns can use the same words, and the word check can make the same mistake. In both cases the card stays, so you can see the concern.
  • A command that only runs tests counts as "files changed". Then the agent can wake again. The limit of 6 stops this.
  • Some modes have no screen for the message (RPC and ACP). In these modes, the stop is silent, as it is now.
For engineers: how to make the change
  • Changes are in extensions/advisor-concern-wake.ts and extensions/concern-match.ts. The current guards stay: idle wait, skip when you queued a message, drop at session change, off in print and JSON mode, aside delivery.
  • Question 1: when hasNativeJudge is true, one call to the host judge (resolveJudge from @oh-my-pi/pi-coding-agent/judgment) with one Choice question per new concern: which earlier concern raises the same issue, or none. Without a native judge, on an error, or after 15 s: word overlap (Jaccard ≥ 0.5, words folded as core's normalizeAdvisorNote). Core already removes exact repeats.
  • Question 2: set lastWakeChangedFiles = false when the wake is sent. On tool_execution_end in the woken turn, set it to true if isError is false and the tool is edit, write, ast_edit, bash, eval, or task. Before the first wake, the value is true. If no turn starts (plan mode, interrupt), the value stays false.
  • Question 3: MAX_WAKES_PER_PROMPT = 6.
  • Message: ctx.ui.notify(text, "info") when ctx.hasUI.
  • Reset: on before_agent_start (your prompt) and after a session switch, branch, or tree jump.
  • Tests: similar concern stays a card; no file change then a new concern gives a message; a chain with file changes wakes 6 times, then gives a message; your prompt resets all.
