Advisor concern follow-up

How the advisor-concern-wake extension makes the agent act on an advisor concern that arrives after its final answer, and where OMP core stays in charge.

Can issue #9074 (can1357/oh-my-pi) be an extension? Partly. The after-final-answer half, yes: OMP shows a late concern as a card, and an extension can see that card and start a new turn. The mid-turn half, no: core's advise tool holds non-blocker notes until the turn ends, before any extension event fires. Held notes are released at the final answer, so the extension still catches them, only later.

Routing

What happens to one advisor concern. The extension adds one step between the preserved card and a new turn; the final decision to start that turn stays with core.

Lifecycle

One run over time. The extension never talks to the agent directly: it hands the note back to core, and core decides whether a turn starts.

Before and after

Only one cell changes: a concern that arrives after the final answer. Everything else is core behavior the extension leaves alone.

Why aside, not steer

  • On an idle session, core's aside branch checks plan mode, a user interrupt still in effect (autoResumeSuppressed), and ACP deferral before starting a turn.
  • A steer with triggerTurn only checks ACP deferral, so it would restart a run you stopped with Esc.
  • Core's own interrupt flag replaces the extension's earlier guess from stopReason: "aborted", which missed some stops.

Guards in the extension

  • Only concern notes; blockers already wake the agent in core.
  • Waits for idle: core can show the card while it is still finishing up.
  • Drops pending notes if the agent writes more output first; it already has them.
  • Skips if you queued a message; at most 2 wakes per prompt.
  • Drops waiting notes on /new, resume, fork, or /tree, so an old conversation's concern never lands in the new one.

Limits

  • advisor.immuneTurns cooldown is core-private; it does not delay these wakes.
  • No mid-turn response: core holds the note before extensions see it.
  • Off in print and JSON mode: print mode prints the final answer, only records late notes, then exits, so a woken turn would never be shown.
